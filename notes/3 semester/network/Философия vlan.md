В нынешних реалиях невозможно представить полноценную корпоративную сеть без VLAN. Представьте, что на вас совершили атаку, а все устройства подключены напрямую к одному коммутатору без разделения. Злоумышленник окажется в выигрышной позиции, получив L2-доступ ко всем устройствам в сети. Кроме того, хранение всех узлов в одном бродкаст-домене приводит к рискам широковещательных штормов, способных перегрузить сетевое оборудование. Именно для решения этих проблем был введен VLAN.

---

**VLAN (Virtual Local Area Network)** — технология разделения единой физической сети на изолированные логические сегменты. VLAN использует тегирование трафика, закрепляя за кадрами уникальный идентификатор (VLAN ID). Это позволяет объединять компьютеры в общую подсеть, даже если они физически подключены к разным коммутаторам. Например, если отдел разработки находится на 4 и 5 этажах, мы закрепляем за нужными портами необходимый тег, создавая единый L2-сегмент без необходимости тянуть отдельные физические кабели через весь офис.

Порты коммутатора разделяют на два основных класса: **порты доступа (Access)** и **магистральные порты (Trunk)**.

### 1. Порты доступа (Access)
Access-порты предназначены для подключения конечных устройств (ПК, серверов, принтеров), которые ничего не знают про теги 802.1Q. За таким портом закрепляется один конкретный VLAN ID. 

Например, за портом `Et1` сидит ПК разработчика, который по стандарту компании должен находиться в `VLAN 10`. При получении нетегированного кадра от ПК коммутатор помещает его во внутренний `VLAN 10`. При передаче кадра через Trunk-порт коммутатор модифицирует Ethernet-кадр, добавляя 4-байтовый заголовок 802.1Q с информацией о теге.

Пример конфигурации Arista EOS / Cisco IOS:
```text
interface Et1
   switchport mode access
   switchport access vlan 10
````

_(Не забываем предварительно создать сам VLAN в базе коммутатора)._

### 2. Магистральные порты (Trunk)

Trunk-порты служат для соединения сетевых устройств между собой (коммутатор-коммутатор, коммутатор-роутер) и умеют передавать трафик сразу множества VLAN по одному физическому кабелю.

Пример конфигурации:

Plaintext

```
interface Et1
   switchport mode trunk
   switchport trunk allowed vlan 10,20
```

При передаче кадра через транк используется стандарт **IEEE 802.1Q**. Вот как выглядит структура такого кадра в дампе `tshark`:

Bash

```
802.1Q Virtual LAN, PRI: 0, DEI: 0, ID: 10
    0. .... .... .... = Priority: Best Effort (default) (0) 
    ...0 .... .... .... = Drop Eligible: Ineligible (0)      
    .... 0000 0000 1010 = VLAN ID: 10                           
```

### 3. Native VLAN и безопасность

Отдельного внимания заслуживает концепция **Native VLAN** — это специальный VLAN в рамках транка, трафик которого передается **без 802.1Q тега**.

По умолчанию на оборудовании Native VLAN равен `VLAN 1`. Если оставить его неизменным, сеть становится уязвимой к атакам класса _VLAN Hopping / Double Tagging_, а любой случайно прилетевший нетегированный кадр попадает прямо в дефолтный `VLAN 1`, где обычно находятся интерфейсы управления.

Для защиты сети применяется Best Practice: переопределение Native VLAN на неиспользуемый «тупиковый» VLAN (например, `999`):

Plaintext

```
switchport trunk native vlan 999
```

**Как это работает:** Любой случайно или злонамеренно отправленный нетегированный кадр при попадании в транк принудительно помещается в `VLAN 999`. А так как к `VLAN 999` не подключен ни один реальный хост или интерфейс, кадр просто отбрасывается в буфере коммутатора.

**А что со служебным трафиком?** Служебные L2-протоколы (STP, LLDP, CDP), которые также передаются без тега, не сгорают в Native VLAN 999. Они отправляются на специальным образом зарезервированные Multicast MAC-адреса (например, `01:80:C2:00:00:00` для STP). Коммутатор перехватывает их аппаратно еще на входе и отправляет напрямую в Control Plane для обработки процессором.
