Управление процессами в Linux строится на отслеживании их идентификаторов (**PID** — Process ID, **PPID** — Parent Process ID), статусов выполнения и передаче управленческих сигналов через ядро.

---

## ps (Process Status)

Утилита для получения статического «снимка» (snapshot) текущих запущенных процессов.

**Синтаксис:**

```bash
ps [опции]

```

Поддерживает три стиля синтаксиса: **UNIX/POSIX** (с дефисом `-ef`), **BSD** (без дефиса `aux`) и **GNU** (длинные ключи `--forest`).

### Основные флаги

* **Выбор процессов:**
* `a` (BSD) — показать процессы всех пользователей, связанных с терминалом (TTY).
* `x` (BSD) — показать процессы, не привязанные к TTY (фоновые демоны).
* `-e` / `-A` (UNIX) — выбрать абсолютно все процессы в системе.
* `-u USER` — фильтрация процессов по эффективному имени или ID пользователя.
* `-p PID` — вывести информацию строго по указанному PID.


* **Форматирование вывода:**
* `u` (BSD) — расширенный пользовательский формат (USER, %CPU, %MEM, VSZ, RSS, STAT и т. д.).
* `-f` (UNIX) — полноформатный вывод (включает PPID, STIME, C).
* `-o FORMAT` — пользовательский набор колонок для вывода (например, `-o pid,ppid,cmd,%cpu`).
* `--sort=[+|-]KEY` — сортировка по полю (`+` возрастание, `-` убывание).
* `f` / `--forest` — отобразить древовидную иерархию связей родительских и дочерних процессов.



---

### Практические примеры с разбором

```bash
ps aux | grep -v grep | grep nginx

```

> **Что делает:** Выводит полный список процессов всех пользователей с детальной информацией (`aux`) и фильтрует только строки с поисковым словом `nginx`, исключая сам процесс `grep`.

```bash
ps -eo pid,ppid,user,%cpu,%mem,cmd --sort=-%cpu | head -n 11

```

> **Что делает:** Формирует кастомный вывод столбцов (`-o`), отсортированный по убыванию потребления CPU (`--sort=-%cpu`), и выводит шапку с ТОП-10 самыми ресурсоемкими процессами.

```bash
ps -ef --forest

```

> **Что делает:** Отображает список всех процессов (`-e`) в полном формате (`-f`) в виде графического дерева связей процессов (`--forest`), позволяя определить, какой процесс породил конкретный дочерний поток.

## top

Интерактивный консольный монитор процессов в реальном времени.

**Синтаксис:**

```bash
top [опции]

```

### Разбор шапки (Header)

1. **Load Average:** Средняя длина очереди выполнения за 1, 5 и 15 минут.
2. **Tasks:** Общее количество процессов и их статусы (running, sleeping, stopped, zombie).
3. **%Cpu(s):**
* `us` (user) — пользовательские процессы.
* `sy` (system) — процессы ядра.
* `ni` (nice) — процессы с измененным приоритетом.
* `id` (idle) — простой CPU.
* `wa` (iowait) — ожидание завершения операций ввода-вывода (диск/сеть).
* `hi` / `si` — аппаратные и программные прерывания.
* `st` (steal time) — время, забранное гипервизором виртуализации.


4. **MiB Mem / Swap:** Использование оперативной памяти и раздела подкачки (total, free, used, buff/cache).

### Горячие клавиши в интерактивном режиме

* `P` — сортировка процессов по использованию **CPU** (по умолчанию).
* `M` — сортировка процессов по использованию **RAM** (памяти).
* `N` — сортировка по **PID**.
* `T` — сортировка по суммарному времени работы (**TIME+**).
* `k` — отправить сигнал процессу (запрашивает PID и номер сигнала).
* `r` — изменить приоритет процесса (**renice**).
* `1` — развернуть/свернуть отображение загрузки по каждому ядру CPU отдельно.
* `c` — переключить режим отображения имени команды (краткое имя / полный путь с аргументами).
* `u` — фильтрация списка по конкретному пользователю.
* `q` — выход из утилиты.

### Флаги запуска из командной строки

* `-b` (`batch mode`) — пакетный режим для вывода в файл или скрипты без интерактивного TTY.
* `-n N` — завершить работу после `N` обновлений экрана.
* `-d SEC` — задержка обновления экрана в секундах (например, `top -d 1`).
* `-p PID` — мониторинг только конкретного PID (можно передавать через запятую: `-p 1024,2048`).

---

### Практические примеры с разбором

```bash
top -b -n 1 -o %MEM | head -n 20

```

> **Что делает:** Запускает `top` в неинтерактивном однократном режиме (`-b -n 1`), сортируя выводимый список по использованию оперативной памяти (`-o %MEM`), и выводит первые 20 строк.

```bash
top -u www-data

```

> **Что делает:** Запускает мониторинг процессов, принадлежащих исключительно системному пользователю `www-data`.

## Сигналы и утилиты управления: kill, pkill, killall

**Сигнал** — это асинхронное уведомление, посылаемое процессу ядром или другим процессом для изменения его поведения.

### Основные сигналы Linux

| Номер | Название | Описание | Можно ли перехватить/игнорировать? |
| --- | --- | --- | --- |
| **1** | `SIGHUP` | Перезагрузка конфигурации процесса / обрыв терминала | Да |
| **2** | `SIGINT` | Сигнал прерывания с клавиатуры (`Ctrl + C`) | Да |
| **3** | `SIGQUIT` | Завершение процесса с созданием core dump (`Ctrl + \`) | Да |
| **9** | `SIGKILL` | **Немедленное принудительное уничтожение** процесса ядром | **НЕТ** |
| **15** | `SIGTERM` | **Корректное завершение** (сигнал по умолчанию). Дает время закрыть файлы | Да |
| **18** | `SIGCONT` | Возобновление выполнения ранее остановленного процесса | Да |
| **19** | `SIGSTOP` | Приостановка выполнения процесса (аналог `Ctrl + Z`) | **НЕТ** |

---

### kill

Отправляет указанный сигнал процессу по его **PID**.

```bash
kill [сигнал] PID

```

#### Примеры:

```bash
kill 4521

```

> **Что делает:** Отправляет сигнал `SIGTERM` (15) процессу с PID 4521. Процесс перехватывает сигнал, корректно закрывает соединения, сохраняет состояние и завершается.

```bash
kill -9 4521  # или kill -SIGKILL 4521

```

> **Что делает:** Принудительно уничтожает процесс 4521 на уровне ядра. Процесс не успевает очистить ресурсы или сохранить данные. Используется, только если процесс завис и не реагирует на `SIGTERM`.

```bash
kill -HUP $(pgrep -f nginx)

```

> **Что делает:** Отправляет сигнал `SIGHUP` (1) главному процессу Nginx для перезагрузки его конфигурационных файлов без остановки обработки сетевых соединений.

### pkill и killall

Утилиты для отправки сигналов процессам по их **имени или атрибутам**, избавляющие от необходимости вручную искать PID.

* **`pkill`** — ищет процессы по регулярному выражению имени, пользователю или TTY.
* **`killall`** — отправляет сигнал всем процессам, **точно совпавшим** по имени.

#### Примеры:

```bash
pkill -f "python3 script.py"

```

> **Что делает:** Ищет и отправляет `SIGTERM` всем процессам, в полной строке запуска которых (`-f`) встречается `"python3 script.py"`.

```bash
pkill -9 -u student

```

> **Что делает:** Принудительно завершает (`-9`) абсолютно все процессы, принадлежащие пользователю `student`.

```bash
killall -v nginx

```

> **Что делает:** Отправляет `SIGTERM` всем процессам с точным именем `nginx` и выводит отчет о выполненных действиях (`-v`).

## Таблица состояний процессов (Колонка STAT в ps)

| Буква | Состояние | Описание |
| --- | --- | --- |
| **`R`** | Running / Runnable | Процесс выполняется или готов к выполнению (находится в очереди к CPU). |
| **`S`** | Interruptible Sleep | Спящий процесс. Ожидает завершения события (I/O, сетевой пакет, таймер). Реактивен к сигналам. |
| **`D`** | Uninterruptible Sleep | Непрерывно спящий (обычно блокировка на уровне аппаратного I/O). **Не реагирует на `kill -9**`. |
| **`Z`** | Zombie | Завершенный процесс (`defunct`). Освободил память, но ждет, пока родитель прочитает его код возврата. |
| **`T`** | Stopped | Остановлен сигналом остановки (`SIGSTOP`) или под управлением отладчика (`gdb`). |

### Дополнительные модификаторы состояния (например, `Ss+`, `R<`):

* `<` — высокий приоритет (high priority).
* `N` — низкий приоритет (low priority / nice).
* `L` — страницы памяти заблокированы в RAM (`real-time` / `custom I/O`).
* `s` — лидер сессии (session leader).
* `l` — многопоточный процесс (multi-threaded).
* `+` — процесс выполняется в фоновом/активном режиме на переднем плане (foreground group).

## Сводная схема базовых действий

```
  [Создание процесса]
          │
          ▼
   ┌──────────────┐      SIGSTOP (19)      ┌──────────────┐
   │  R (Running) │ ─────────────────────> │ T (Stopped)  │
   └──────────────┘ <───────────────────── └──────────────┘
          │              SIGCONT (18)
          │ Ожидание I/O
          ▼
   ┌──────────────┐      SIGTERM (15)      ┌──────────────┐
   │ S (Sleeping) │ ─────────────────────> │ Z (Zombie)   │ ──(Родитель вызвал wait)──> [Удален из системы]
   └──────────────┘      SIGKILL (9)       └──────────────┘

```
