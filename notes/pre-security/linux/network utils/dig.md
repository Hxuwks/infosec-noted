**dig** (Domain Information Groper) — это мощная и гибкая утилита командной строки из пакета BIND для опроса DNS-серверов и диагностики работы службы доменных имен. Она является стандартом де-факто для сетевых инженеров благодаря детальному выводу ответов, флагов и заголовков.

**nslookup** (Name Server Lookup) — более простая кроссплатформенная утилита (доступна в Linux, macOS и Windows) для быстрого получения IP-адресов по имени и наоборот, а также для выполнения базового интерактивного аудита DNS.

# Часть 1: DIG (Domain Information Groper)

**Синтаксис:**

```bash
dig [@server] [name] [type] [опции]

```

## Основные флаги и параметры `dig`

* `@server` — указывает конкретный DNS-сервер для запроса (например, `@1.1.1.1` или `@8.8.8.8`) в обход системного резолвера.
* `type` — тип запрашиваемой ресурсной записи (`A`, `AAAA`, `MX`, `NS`, `TXT`, `SOA`, `PTR`, `ANY`).
* `+short` — сокращенный вывод (выводит только чистый результат, например, только IP-адрес).
* `+trace` — пошаговая трассировка резолвинга домена от корневых (Root) серверов до авторитетных DNS зоны.
* `-x IP` — обратный DNS-запрос (Reverse Lookup) для определения домена по IP-адресу.
* `+noall +answer` — оставить в выводе только секцию ответа (Answer Section), отбросив служебную информацию.

## Практические сценарии использования `dig`

### 1. Базовый запрос A-записи

```bash
dig example.com A

```

> **Что делает:** Запрашивает IPv4-адрес домена `example.com` через системный резолвер.

### 2. Запрос через публичный DNS с коротким выводом

```bash
dig @1.1.1.1 example.com +short

```

> **Что делает:** Опрашивает сервер Cloudflare (`1.1.1.1`) и выводит исключительно IP-адрес без лишних секций.

### 3. Просмотр почтовых серверов (MX-записи)

```bash
dig iana.org MX +noall +answer

```

> **What it does:** Запрашивает MX-записи почтовых шлюзов с приоритетами, фильтруя вывод только до нужного блока.

### 4. Полная трассировка цепочки делегирования (`+trace`)

```bash
dig example.com +trace

```

> **Что делает:** Имитирует полный рекурсивный поиск: сначала опрашивает корневые сервера (`.`), затем серверы зоны `.com`, и в конце — авторитетные серверы самого домена. Незаменимо при отладке зависшего или сломанного резолва.

### 5. Обратный DNS-запрос (PTR)

```bash
dig -x 8.8.8.8 +short

```

> **Что делает:** Превращает IP-адрес обратно в доменное имя (например, `dns.google`).

# Часть 2: NSLOOKUP (Name Server Lookup)

**Синтаксис:**

```bash
nslookup [домен_или_IP] [сервер]

```

## Основные параметры `nslookup`

* `-type=RECORD` — задание типа записи (`-type=a`, `-type=mx`, `-type=ns`, `-type=txt`, `-type=any`).
* `-port=PORT` — отправка запроса на нестандартный порт DNS.
* Без аргументов запускает **интерактивный режим** (когда можно вводить множество запросов подряд).

## Практические сценарии использования `nslookup`

### 1. Простой поиск IP-адреса

```bash
nslookup google.com

```

> **Что делает:** Выводит сервер, через который производился опрос, и соответствующие IP-адреса (`A` и `AAAA` записи).

### 2. Запрос специфических записей (например, NS)

```bash
nslookup -type=ns google.com

```

> **Что делает:** Запрашивает авторитетные серверы имен (Name Servers), обслуживающие указанный домен.

### 3. Запрос к конкретному DNS-серверу

```bash
nslookup yandex.ru 8.8.8.8

```

> **Что делает:** Принудительно запрашивает резолв домена `yandex.ru` у публичного DNS Google (`8.8.8.8`).

### 4. Интерактивный режим отладки

```bash
nslookup
> server 1.1.1.1
> set type=mx
> github.com
> exit

```

> **Что делает:** Позволяет войти в интерактивную консоль, сменить целевой сервер, настроить тип запрашиваемых записей и выполнить серию бывших проверок, не перезапуская команду каждый раз.

## Сводная шпаргалка: dig vs nslookup

| Задача | Команда `dig` | Команда `nslookup` |
| --- | --- | --- |
| **Быстрый поиск IP** | `dig example.com +short` | `nslookup example.com` |
| **Запрос через конкретный DNS** | `dig @8.8.8.8 example.com` | `nslookup example.com 8.8.8.8` |
| **Запрос MX-записей (почта)** | `dig example.com MX` | `nslookup -type=mx example.com` |
| **Обратный поиск (PTR / IP в имя)** | `dig -x 192.168.1.1` | `nslookup 192.168.1.1` |
| **Пошаговая трассировка корня** | `dig example.com +trace` | *Не поддерживает* |
