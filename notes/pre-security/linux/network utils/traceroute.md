**traceroute** (в Windows — `tracert`) — это утилита сетевой диагностики, предназначенная для определения маршрута следования IP-пакетов от локального узла к целевому серверу. Она позволяет определить каждый промежуточный маршрутизатор (хоп / hop) и задержку (RTT) на каждом участке пути.

---

## 1. Принцип работы (Под капотом)

`traceroute` использует поле **TTL (Time to Live)** в заголовке IP-пакета и служебные сообщения протокола **ICMP**:

1. **TTL = 1:** Отправляется первый пакет с TTL=1. Первый маршрутизатор на пути уменьшает TTL на 1 (до 0), отбрасывает пакет и возвращает отправителю сообщение **`ICMP Time Exceeded`** (Type 11, Code 0). Из этого ответа утилита узнает IP-адрес первого хопа и задержку.
2. **Инкремент TTL:** Следующий пакет отправляется с TTL=2. Он проходит первый маршрутизатор, но отбрасывается вторым, возвращающим `ICMP Time Exceeded`.
3. **Финал:** Процесс повторяется (TTL=3, TTL=4...), пока пакет не достигнет назначения:
* **Linux `traceroute` по умолчанию** отправляет **UDP-пакеты** на случайные высокие порты (обычно `33434-33534`). Получив пакет, целевой хост отвечает сообщением **`ICMP Destination Unreachable / Port Unreachable`** (Type 3, Code 3), что сигнализирует об окончании трассировки.
* **Windows `tracert` по умолчанию** отправляет **ICMP Echo Request** (как `ping`). Целевой хост отвечает **`ICMP Echo Reply`**.

## 2. Основные флаги Linux `traceroute`

Синтаксис:

```bash
traceroute [опции] host

```

### Выбор протокола зондирования

* `-I` (`--icmp`) — использовать **ICMP Echo Request** вместо UDP (аналог поведения Windows `tracert`). Удобно, если UDP заблокирован фаерволом.
* `-T` (`--tcp`) — использовать **TCP SYN** пакеты (по умолчанию на порт `80`). Позволяет проходить через строго настроенные фаерволы (stateful firewalls), пропускающие веб-трафик.
* `-U` (`--udp`) — использовать UDP на конкретный порт (указывается флагом `-p`).

### Настройка параметров отправки

* `-n` — не резолвить IP-адреса в доменные имена (DNS). **Значительно ускоряет трассировку.**
* `-p PORT` — задать целевой порт (для TCP/UDP).
* `-m HOPS` (`--max-hops`) — максимальное количество хопов (по умолчанию `30`).
* `-q N` (`--queries`) — количество пробных пакетов на каждый хоп (по умолчанию `3`).
* `-w SEC` (`--wait`) — время ожидания ответа на пакет в секундах (по умолчанию `5.0`).
* `-f TTL` (`--first`) — начальное значение TTL (например, начать сразу с 5-го хопа).
* `-4` / `-6` — принудительно использовать IPv4 или IPv6.
* `-A` (`--as-path-lookups`) — показывать номера автономных систем (**AS number**) для каждого IP-адреса хопа.

## 3. Разбор вывода

```text
traceroute to google.com (142.250.185.206), 30 hops max, 60 byte packets
 1  _gateway (192.168.1.1)  0.312 ms  0.285 ms  0.241 ms
 2  10.100.0.1 (10.100.0.1)  2.115 ms  2.040 ms  1.988 ms
 3  185.12.10.1 (185.12.10.1)  5.420 ms  5.311 ms  5.190 ms
 4  * * *
 5  142.250.185.206 (142.250.185.206)  12.102 ms  11.954 ms  11.890 ms

```

* **`1, 2, 3...`** — номер хопа (соответствует значению TTL).
* **`_gateway (192.168.1.1)`** — доменное имя и IP-адрес маршрутизатора.
* **`0.312 ms 0.285 ms 0.241 ms`** — время отклика (RTT) для каждого из 3 запущенных пакетов.
* **`* * *`** — маршрутизатор на данном хопе не ответил за отведенный таймаут (`-w`). Причины:
1. Маршрутизатор настроен игнорировать и не генерировать сообщения `ICMP Time Exceeded` (защита / Rate Limiting).
2. Фаервол блокирует входящие/исходящие пробы или ICMP-ответы.

## 4. Практические сценарии использования

### 1. Трассировка через жесткие фаерволы (TCP SYN)

```bash
sudo traceroute -n -T -p 443 google.com

```

> **Что делает:** Отправляет TCP-пакеты с флагом `SYN` на порт HTTPS (443) без DNS-резолва (`-n`). Это пробивает большинство корпоративных фаерволов, блокирующих обычный UDP/ICMP трафик.

---

### 2. Определение автономных систем (BGP / AS Path)

```bash
traceroute -A 8.8.8.8

```

> **Что делает:** Добавляет в вывод информацию о том, к какой Автономной Системе (AS) и провайдеру относится каждый промежуточный IP-адрес (например, `[AS15169 Google LLC]`).

---

### 3. Быстрая диагностика без задержек на DNS

```bash
traceroute -n -I 1.1.1.1

```

> **Что делает:** Выполняет трассировку с помощью ICMP-запросов (`-I`) и отключает резолв имен (`-n`), обеспечивая мгновенный вывод результатов.

---

## 5. Альтернативы и современные преемники

* **`mtr` (My Traceroute)** — объединяет функционал `traceroute` и `ping`. Выводит интерактивную обновляемую таблицу со статистикой потерь пакетов (%) и задержек в реальном времени.
* **`tcptraceroute`** — утилита для TCP-трассировки, работающая через сырые сокеты (полезно, если стандартный `traceroute -T` недоступен).
* **`paris-traceroute`** — усовершенствованная утилита, решающая проблему искажения маршрутов при наличии ECMP (Equal-Cost Multi-Path) балансировки трафика.
