**Telnet** — это старый сетевой протокол и одноименная утилита, предназначенная для обеспечения двусторонней интерактивной связи через терминал.

> **Никогда не используйте `telnet` для удаленного управления серверами.** Протокол передает все данные (включая логин и пароль) в **открытом виде** (plaintext). Любой участник сети может перехватить трафик с помощью простого сниффера (`tcpdump`/Wireshark). Для удаленного доступа используйте **SSH**.

Сегодня `telnet` используется исключительно как **инструмент для отладки сетевых соединений** и проверки доступности TCP-портов.

---

## 1. Зачем использовать telnet в 2026 году?

1. **Проверка доступности порта:** Самый простой способ узнать, открыт ли порт на удаленном хосте.
2. **Тестирование протоколов вручную:** Можно «поговорить» с сервером на языке протокола (например, HTTP, SMTP или POP3), отправляя команды напрямую.
3. **Диагностика фаерволов:** Проверка, не блокирует ли промежуточное устройство пакеты `SYN`.

---

## 2. Основные сценарии использования

### А. Проверка TCP-порта

Если вам нужно быстро проверить, слушает ли сервис на определенном порту:

```bash
telnet 192.168.1.100 80

```

* **Успех:** Вы увидите сообщение `Connected to 192.168.1.100`.
* **Отказ (фильтрация/сервис не запущен):** `Connection refused` (порт закрыт) или `Connection timed out` (пакеты отбрасываются фаерволом).

### Б. Ручное тестирование SMTP (почты)

Вы можете имитировать отправку письма, чтобы проверить работу почтового сервера:

```bash
telnet smtp.example.com 25

```

После подключения можно вводить команды:

1. `HELO example.com`
2. `MAIL FROM:<me@example.com>`
3. `RCPT TO:<target@example.com>`
4. `DATA`
5. *Пишете текст письма*
6. `.` (точка и Enter для завершения)
7. `QUIT`

### В. Ручное тестирование HTTP

Можно отправить сырой HTTP-запрос веб-серверу:

```bash
telnet google.com 80

```

Введите (быстро):

```http
GET / HTTP/1.1
Host: google.com
Connection: close


```

*(После этого нажмите дважды Enter, чтобы отправить запрос)*.

---

## 3. Выход из telnet (Escape Sequence)

Это главная сложность для новичков. Если вы подключились к серверу, то просто выйти через `exit` или `Ctrl+C` часто не получается (так как вы находитесь внутри сессии).

Для выхода нужно отправить **Escape-последовательность**:

1. Нажмите **`Ctrl` + `]**` (откроется командная строка telnet: `telnet>`).
2. Введите **`quit`** и нажмите Enter.

---

## 4. Почему telnet заменяют другие инструменты?

`telnet` — это «дедушка» сетевых утилит. У него есть недостатки:

* Не умеет работать с UDP (только TCP).
* Не умеет проверять SSL/TLS-соединения (HTTPS/SMTPS).
* Мало гибкости в настройке таймаутов.

### Современные альтернативы:

| Утилита | Лучше всего подходит для... |
| --- | --- |
| **`nc` (netcat)** | «Швейцарский нож». Умеет TCP, UDP, прослушивание портов, создание серверов и передачу файлов. |
| **`curl`** | Идеален для тестирования HTTP/HTTPS API (показывает заголовки, тело ответа). |
| **`openssl s_client`** | Единственный способ отладки TLS-рукопожатий и проверки сертификатов на HTTPS/SMTPS портах. |
| **`nmap`** | Сканирование целых диапазонов портов и сетей, определение версий ОС и сервисов. |

#### Пример замены `telnet` на `nc` (Netcat):

```bash
# Проверка порта без перехода в интерактивный режим
nc -zv 192.168.1.100 80

```

* `-z`: сканирование без отправки данных.
* `-v`: подробный вывод (verbose).
