**iptables** — это интерфейс командной строки для управления подсистемой **Netfilter** в ядре Linux. Он позволяет фильтровать сетевой трафик, выполнять трансляцию сетевых адресов (NAT) и модифицировать IP-пакеты.

Архитектура iptables строятся на трех базовых понятиях: **Таблицы (Tables)**, **Цепочки (Chains)** и **Правила (Rules)** с назначенными **Действиями (Targets)**.

---


## 1. Таблицы (Tables)

Таблицы группируют правила по их функциональному назначению:

1. **`filter`** *(используется по умолчанию)* — основная таблица для фильтрации трафика (блокировка/разрешение пакетов).
2. **`nat`** — трансляция сетевых адресов. Используется при пробросе портов (DNAT) или организации общего доступа в интернет (SNAT/Masquerade).
3. **`mangle`** — модификация заголовков пакетов (изменение TTL, TOS, установка маркерных меток `MARK` для дальнейшей маршрутизации).
4. **`raw`** — управление отслеживанием состояний соединений (conntrack). Используется для исключения пакетов из подсистемы conntrack (цель `NOTRACK`) с целью оптимизации при DDoS.
5. **`security`** — установка меток безопасности SELinux/AppArmor на пакеты.

---

## 2. Цепочки (Chains)

Цепочки определяют **момент/точку**, в которой пакет проверяется правилами:

* **`PREROUTING`** — срабатывает сразу при поступлении пакета в сетевой интерфейс, *до* принятия решения о маршрутизации.
* **`INPUT`** — срабатывает, если пакет предназначен непосредственно данному локальному хосту.
* **`FORWARD`** — срабатывает, если пакет транзитный (проходит через хост на другое устройство, требует включенного `net.ipv4.ip_forward`).
* **`OUTPUT`** — срабатывает для пакетов, сгенерированных локальными процессами самого хоста.
* **`POSTROUTING`** — срабатывает перед отправкой пакета в провод, *после* принятия решения о маршрутизации.

---

## 3. Действия (Targets)

Если пакет соответствует условиям правила, к нему применяется одно из действий (`-j / --jump`):

* **`ACCEPT`** — пропустить пакет далее по стеку.
* **`DROP`** — тихо отбросить пакет без уведомления отправителя.
* **`REJECT`** — отбросить пакет и отправить отправителю ICMP-сообщение об ошибке (`port-unreachable`).
* **`LOG`** — записать информацию о пакете в системный журнал (`dmesg` / `syslog`) и продолжить обработку другими правилами.
* **`DNAT`** *(только в nat PREROUTING/OUTPUT)* — изменить IP-адрес/порт назначения пакета.
* **`SNAT`** *(только в nat POSTROUTING)* — изменить IP-адрес источника пакета на статический IP.
* **`MASQUERADE`** *(только в nat POSTROUTING)* — модификация SNAT для динамических внешних IP-адресов.

## 4. Синтаксис и ключи командной строки

**Базовый шаблон:**

```bash
iptables [-t таблица] КОМАНДА цепочка [УСЛОВИЯ] -j ДЕЙСТВИЕ

```

### Основные команды управления (`КОМАНДА`)

| Флаг | Описание |
| --- | --- |
| `-A` (`--append`) | Добавить правило в конец цепочки |
| `-I` (`--insert`) | Вставить правило в начало цепочки (или на указанную позицию: `-I INPUT 1`) |
| `-D` (`--delete`) | Удалить правило (по номеру или точной формулировке) |
| `-L` (`--list`) | Вывести список правил в цепочках |
| `-F` (`--flush`) | Очистить все правила в указанной таблице/цепочке |
| `-P` (`--policy`) | Установить политику по умолчанию (`iptables -P INPUT DROP`) |
| `-N` / `-X` | Создать новую пользовательскую цепочку / Удалить пустую пользовательскую цепочку |

### Условия фильтрации (`УСЛОВИЯ`)

* `-p` (`--protocol`) — протокол (`tcp`, `udp`, `icmp`, `all`).
* `-s` (`--source`) — IP-адрес или подсеть источника (`192.168.1.50`, `10.0.0.0/24`).
* `-d` (`--destination`) — IP-адрес или подсеть назначения.
* `-i` (`--in-interface`) — входящий сетевой интерфейс (`eth0`, `wlan0`).
* `-o` (`--out-interface`) — исходящий сетевой интерфейс.
* `--sport` / `--dport` — порт источника / назначения (требует указания `-p tcp` или `-p udp`).
* `-m state` / `-m conntrack` — модуль отслеживания состояний соединений (`--ctstate NEW,ESTABLISHED,RELATED`).

## 5. Практические сценарии использования

### Сценарий A: Базовый защитный экран (Stateful Firewall Baseline)

Классический подход: запретить всё входящее по умолчанию, разрешить loopback, отвечать на существующие соединения и открыть только нужные порты.

```bash
# 1. Очистка существующих правил
iptables -F
iptables -X

# 2. Установка политики по умолчанию: DROP для входа и транзита
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 3. Разрешаем трафик на интерфейсе обратной петли (lo)
iptables -A INPUT -i lo -j ACCEPT

# 4. Разрешаем входящий трафик для УЖЕ УСТАНОВЛЕННЫХ соединений
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 5. Разрешаем входящий SSH (22) и HTTPS (443)
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 6. Отбрасываем невалидные пакеты
iptables -A INPUT -m conntrack --ctstate INVALID -j DROP

```

---

### Сценарий B: Проброс портов (DNAT / Port Forwarding)

Перенаправление входящего HTTPS-трафика с внешнего интерфейса (`eth0`, порт `8443`) на внутренний веб-сервер (`192.168.1.10:443`).

```bash
# 1. Включаем маршрутизацию в ядре
sysctl -w net.ipv4.ip_forward=1

# 2. Изменяем адрес назначения пакета до принятия решения о маршрутизации
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8443 -j DNAT --to-destination 192.168.1.10:443

# 3. Разрешаем транзит пакетов в цепочке FORWARD
iptables -A FORWARD -p tcp -d 192.168.1.10 --dport 443 -m conntrack --ctstate NEW,ESTABLISHED,RELATED -j ACCEPT

```

---

### Сценарий C: Настройка NAT / Masquerade (Маршрутизатор для локальной сети)

Предоставление доступа в интернет устройством с двумя сетевыми картами (`eth0` — внешний IP, `eth1` — локальная сеть `192.168.1.0/24`).

```bash
# 1. Разрешаем транзит из локальной сети наружу
iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
iptables -A FORWARD -i eth0 -o eth1 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 2. Маскируем подсеть при выходе во внешнюю сеть
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

```

## 6. Просмотр и сохранение правил

Вывод текущих правил с подробной статистикой байт/пакетов и номерами строк:

```bash
iptables -L -v -n --line-numbers
# -v : вербозный режим (показывает счетчики пакетов/байт и интерфейсы)
# -n : числовой формат (не резолвит IP в домены и порты в имена служб)

```

**Сохранение правил:**
Правила iptables хранятся в оперативной памяти и сбрасываются после перезагрузки.

* **Debian/Ubuntu:** `iptables-save > /etc/iptables/rules.v4` (требует пакет `iptables-persistent`).
* **RHEL/CentOS:** `service iptables save` или `iptables-save > /etc/sysconfig/iptables`.
