**Discovery / базовое**
1. `nmap -sn 192.168.20.0/24` — ping-скан, только discovery живых хостов, без портов
2. `nmap -sL 192.168.20.0/24` — список хостов без отправки пакетов (DNS-резолв)
3. `nmap -PR 192.168.30.0/24` — ARP-ping (надёжнее ICMP внутри одного L2)
4. `nmap -iL targets.txt` — сканить список хостов из файла
5. `nmap -6 fe80::1` — сканирование IPv6

**Типы сканирования портов**
6. `nmap -sS 192.168.20.10` — SYN-скан ("half-open", стандарт де-факто, нужен root)
7. `nmap -sT 192.168.20.10` — full TCP connect-скан (без root, но "шумнее")
8. `nmap -sU 192.168.20.10` — UDP-скан
9. `nmap -sA 192.168.20.10` — ACK-скан (определение фильтрации firewall'ом)
10. `nmap -sW 192.168.20.10` — Window-скан
11. `nmap -sN/-sF/-sX 192.168.20.10` — Null/FIN/Xmas скан (обход простых stateless-фильтров)

**Выбор портов**
12. `nmap -p 80,443 192.168.20.10` — конкретные порты
13. `nmap -p 1-1000 192.168.20.10` — диапазон
14. `nmap -p- 192.168.20.10` — все 65535 портов
15. `nmap -F 192.168.20.10` — fast-скан (топ-100 портов)
16. `nmap --top-ports 20 192.168.20.10` — N самых частых портов

**Fingerprinting**
17. `nmap -sV 192.168.20.10` — определение версий сервисов
18. `nmap -O 192.168.20.10` — OS fingerprinting
19. `nmap -A 192.168.20.10` — агрегат: -sV -O -sC -traceroute
20. `nmap --version-intensity 9 192.168.20.10` — максимально агрессивный version-detect

**NSE скрипты**
21. `nmap -sC 192.168.20.10` — дефолтный набор скриптов
22. `nmap --script vuln 192.168.20.10` — скрипты поиска уязвимостей
23. `nmap --script=http-title,http-headers 192.168.20.10` — конкретные скрипты
24. `nmap --script-help banner` — справка по конкретному скрипту

**Timing / уклонение**
25. `nmap -T4 192.168.20.10` — агрессивный тайминг (быстрее, "шумнее")
26. `nmap -T0 192.168.20.10` — paranoid-режим (максимально медленно, для обхода IDS)
27. `nmap -f 192.168.20.10` — фрагментация пакетов
28. `nmap -D RND:5 192.168.20.10` — decoy-скан (маскировка среди фейковых IP)
29. `nmap --scan-delay 500ms 192.168.20.10` — задержка между пакетами

**Вывод**
30. `nmap -oA scan_result 192.168.20.10` — вывод сразу во все форматы (normal/xml/grepable)

## 15 примеров

**1. Полная разведка одного хоста для отчёта**
```
nmap -p- -sV -sC -O -T4 -oA full_scan 192.168.20.10
```
> Все порты + версии + скрипты + ОС + агрессивный тайминг, всё сохраняется в 3 формата разом. Твой базовый "дай мне всё, что можно" на цель.

**2. Тихий скрытный скан через фрагментацию + decoy**
```
nmap -sS -f -D 192.168.20.1,192.168.20.20,ME,192.168.20.30 -T2 192.168.20.10
```
>SYN-скан с фрагментированными пакетами и decoy-адресами вперемешку с реальным (`ME`) — цель видит скан якобы от нескольких хостов сразу. Хорошо показать в статье разницу с обычным `-sS` в логах Suricata/iptables.

**3. Быстрый discovery всей сети без портов (recon-фаза)**
```
nmap -sn -PR 192.168.30.0/24 -oG - | grep Up
```
>Только "кто жив" внутри своего L2-сегмента, через ARP-ping (надёжнее ICMP, который может резаться firewall'ом), с grepable-выводом.

**4. Сравнение видимости сети из разных точек (твой ключевой демо-кейс)**
```
# с dev-pc-01 (VLAN 10)
nmap -p- 192.168.20.10 192.168.20.20 192.168.20.30

# с kali (VLAN 30)
nmap -p- 192.168.20.10 192.168.20.20 192.168.20.30
```
>Один и тот же скан из DEV и USR сегментов — наглядно покажет разницу из-за твоих iptables-правил (DEV видит всё, USR — только 80/tcp на web).

**5. Version + vuln скрипты одновременно на веб-сервисе**
```
nmap -p 80 -sV --script=http-enum,http-headers,http-methods,vuln 192.168.20.10
```
>Энумерация директорий, методов, заголовков и известных уязвимостей одним проходом на nginx.

**6. UDP-скан только по частым портам (UDP по всем 65535 слишком долгий)**
```
nmap -sU --top-ports 50 -T4 192.168.20.30
```
>UDP полный скан может идти часами из-за rate-limiting ICMP; top-ports — практичный компромисс.

**7. ACK-скан для проверки, что именно фильтрует firewall на шлюзе**
```
nmap -sA -p 1-1000 192.168.20.0/24
```
>Запусти с `kali` (USR) — ACK-скан покажет "unfiltered" только на разрешённых политикой портах, это прямая проверка твоих iptables FORWARD-правил снаружи.

**8. TCP connect-скан без root-прав внутри контейнера**
```
nmap -sT -p 1-1000 192.168.20.10
```
>Если запускаешь не от root (в части контейнеров может быть актуально) — единственный вариант, т.к. `-sS` требует raw sockets.

**9. Агрессивный аудит всей серверной подсети разом**
```
nmap -A -T4 -p- 192.168.20.0/24 -oN srv_segment_audit.txt
```
>Полный аудит целого сегмента одним запуском — хорошо для статьи как "снимок" состояния лабы до/после хардненинга правил.

**10. Null/FIN/Xmas — сравнение реакции стека на нестандартные флаги**
```
nmap -sN 192.168.20.10 -p 80,3306
nmap -sX 192.168.20.10 -p 80,3306
```
>Классический пример из теории stateless-firewall bypass — хорошо показать side-by-side с обычным `-sS`, объяснить RFC 793 поведение (нет ответа = open|filtered).

**11. Traceroute + скрипты определения расстояния/маршрута**
```
nmap --traceroute -sV 192.168.10.0/24
```
>Покажет путь через `frr-gateway`/`frr-backup` — полезно для статьи про маршрутизацию и VRRP failover.

**12. Скан с определением banner вручную**
```
nmap -p 3306 --script=mysql-info,banner 192.168.20.30
```
>Если решишь поднять реальную БД (MariaDB) — этот скрипт вытащит версию и метаданные сервера напрямую из хендшейка протокола.

**13. Rate-limited скан для обхода детекта по трафику**
```
nmap -sS --max-rate 5 --scan-delay 1s -T1 192.168.20.10
```
>Специально медленный скан — хороший контраст с `-T4` для демонстрации в Suricata/логах: один палится сразу, второй почти незаметен.

**14. Grepable-вывод + автоматический парсинг открытых портов**
```
nmap -p- -T4 --open -oG - 192.168.20.10 | awk -F: '/Ports/{print $2}'
```
>`--open` показывает только открытые (без closed/filtered шума) — полезно для скриптования дальнейших шагов (например, автоматически передать список портов в другой инструмент).

**15. Полный ping+arp discovery по всем трём сегментам разом (топология-level)**
```
for net in 192.168.10.0/24 192.168.20.0/24 192.168.30.0/24; do
  echo "== $net =="; nmap -sn $net
done
```
>С `kali` эта команда упрётся в firewall на DEV/SRV (ICMP разрешён у тебя правилом `-p icmp -j ACCEPT`, так что discovery, скорее всего, сработает даже через сегменты — а вот порт-скан дальше уже нет). Хороший переход к обсуждению разницы "вижу хост" vs "вижу сервисы".
