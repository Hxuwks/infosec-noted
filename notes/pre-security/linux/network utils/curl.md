**curl** (Client URL) — это утилита командной строки и библиотека (`libcurl`) для передачи данных по различным сетевым протоколам (HTTP, HTTPS, FTP, SFTP, SMTP, POP3, IMAP, TELNET и др.). Является основным инструментом сетевого инженера, разработчика и системного администратора для тестирования API, отладки веб-сервисов, загрузки файлов и анализа сетевых ответов.

**Синтаксис:**

```bash
curl [опции] [URL]

```

---

## Основные флаги по категориям

### 1. HTTP-методы и передача данных

* `-X METHOD` (`--request METHOD`) — указывает HTTP-метод запроса (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `HEAD`, `OPTIONS`).
* `-d DATA` (`--data DATA`) — отправка данных в `POST`-запросе. По умолчанию устанавливает заголовок `Content-Type: application/x-www-form-urlencoded`.
* `--data-raw DATA` — отправка данных без специальной обработки символа `@` (удобно для передачи строк, начинающихся с `@`).
* `--data-binary DATA` — передача данных в бинарном виде «как есть» без удаления символов перевода строки.
* `-F "KEY=VALUE"` (`--form "KEY=VALUE"`) — отправка данных в формате `multipart/form-data`. Используется для загрузки файлов (префикс `@` перед путем к файлу: `-F "file=@/path/to/file"`).
* `-I` (`--head`) — отправка метода `HEAD` (получение только HTTP-заголовков ответа без тела).

### 2. Заголовки, куки и авторизация

* `-H "HEADER: VALUE"` (`--header`) — добавление пользовательского HTTP-заголовка. Можно указывать несколько раз.
* `-A "USER_AGENT"` (`--user-agent`) — переопределение строки `User-Agent`.
* `-u "USER:PASS"` (`--user`) — передача данных для Basic-авторизации (`HTTP Basic Authentication`).
* `-b COOKIES` (`--cookie`) — передача кук на сервер. Передается либо строка `"name=value"`, либо путь к файлу с куками.
* `-c FILE` (`--cookie-jar`) — сохранение полученных от сервера кук (из заголовка `Set-Cookie`) в файл после завершения запроса.
* `-e URL` (`--referer`) — заголовок `Referer` (URL страницы, с которой совершен переход).

### 3. Вывод и сохранение результатов

* `-o FILE` (`--output FILE`) — сохранить тело ответа в указанный файл.
* `-O` (`--remote-name`) — сохранить файл с именем, полученным из URL на сервере.
* `-s` (`--silent`) — «тихий» режим. Скрывает шкалу прогресса и служебные сообщения.
* `-S` (`--show-error`) — используется вместе с `-s`: скрывает прогресс, но **показывает ошибки**, если запрос завершился сбоем.
* `-v` (`--verbose`) — подробный режим отладки. Показывает установку TLS-соединения, отправленные и полученные заголовки (`>` — отправлено, `<` — получено).
* `-i` (`--include`) — включить HTTP-заголовки ответа в итоговый вывод вместе с телом ответа.
* `-w "FORMAT"` (`--write-out`) — вывод пользовательских метрик запроса (HTTP-код, время DNS-резолва, время ответа и т.д.).

### 4. Сетевые настройки, SSL и Прокси

* `-L` (`--location`) — автоматический переход по редиректам (заголовки `301`, `302`, `307`, `308`).
* `-k` (`--insecure`) — отключить проверку валидности SSL/TLS сертификата (игнорировать самоподписанные или просроченные сертификаты).
* `-x PROXY` (`--proxy`) — использование прокси-сервера (поддерживаются `http://`, `https://`, `socks5://`).
* `--resolve HOST:PORT:ADDRESS` — принудительное сопоставление доменного имени с конкретным IP-адресом (аналог временной записи в `/etc/hosts`).
* `-m SEC` (`--max-time`) — максимальное время выполнения всей операции в секундах.
* `--connect-timeout SEC` — максимальное время ожидания установления соединения с сервером.
* `-4` / `-6` — принудительное использование протоколов IPv4 или IPv6.

## Практические сценарии с детальным разбором

### 1. Взаимодействие с REST API (JSON)

```bash
curl -s -S -X POST "https://api.example.com/v1/users" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -d '{"name": "Alice", "role": "admin"}'

```

> **Что делает:** Отправляет `POST`-запрос в тихом режиме (`-s -S`), передавая JSON-структуру (`-d`) с установкой заголовков формата данных (`Content-Type: application/json`) и токена аутентификации (`Authorization: Bearer`).

```bash
curl -X PUT "https://api.example.com/v1/users/42" \
  -H "Content-Type: application/json" \
  -d '{"status": "active"}'

```

> **Что делает:** Выполняет обновление объекта с ID 42 методом `PUT`, обновляя его статус.

```bash
curl -X DELETE "https://api.example.com/v1/users/42" -I

```

> **Что делает:** Отправляет запрос на удаление объекта методом `DELETE` и запрашивает только заголовки ответа (`-I`) для проверки кода ответа (например, `204 No Content` или `200 OK`).

---

### 2. Загрузка и докачка файлов

```bash
curl -L -C - -O "https://releases.ubuntu.com/24.04/ubuntu-24.04-desktop-amd64.iso"

```

> **Что делает:** Загружает файл и сохраняет его с оригинальным именем (`-O`). Флаг `-L` разрешает переход по перенаправлениям, а `-C -` **автоматически возобновляет прерванную загрузку** (докачку) с места обрыва.

```bash
curl -F "file=@/tmp/report.pdf" -F "description=Q3 Report" "https://upload.example.com/upload"

```

> **Что делает:** Отправляет файл `/tmp/report.pdf` и текстовое поле `description` через форму `multipart/form-data` (`-F`). Обратите внимание на символ `@` перед путем к файлу.

---

### 3. Авторизация и работа с сессиями (Cookies)

```bash
# Шаг 1: Авторизация и сохранение кук
curl -s -c cookies.txt -d "username=admin&password=secret" "https://example.com/login"

# Шаг 2: Выполнение запроса с сохраненными куками
curl -s -b cookies.txt "https://example.com/dashboard"

```

> **Что делает:** На первом этапе передает логин и пароль в форме, сохраняя полученную сессионную куку в файл `cookies.txt` (`-c`). На втором этапе загружает защищенную страницу, отправляя ранее сохраненные куки из файла `cookies.txt` (`-b`).

---

### 4. Тестирование виртуальных хостов и bypass DNS (`--resolve`)

```bash
curl -k -v --resolve "example.com:443:192.168.1.100" "https://example.com/health"

```

> **Что делает:** Игнорирует системный DNS и отправляет запрос для домена `example.com:443` строго на IP-адрес `192.168.1.100`. Игнорирует ошибки сертификатов (`-k`) и выводит подробную отладочную информацию TLS-рукопожатия и заголовков (`-v`). Удобно для проверки веб-сервера до смены DNS-записей.

## Глубокая отладка и профилирование производительности (`-w`)

Флаг `-w` (`--write-out`) позволяет вывлекать детальные метрики сетевых задержек, времени установления соединений и кодов ответов.

### Измерение времени запроса по этапам (Latency Profiling):

```bash
curl -s -o /dev/null -w "\
HTTP Status:       %{http_code}\n\
DNS Lookup:        %{time_namelookup}s\n\
TCP Connect:       %{time_connect}s\n\
TLS Handshake:     %{time_appconnect}s\n\
TTFB (First Byte): %{time_starttransfer}s\n\
Total Time:        %{time_total}s\n" \
"https://google.com"

```

> **Что делает:** Выполняет запрос, перенаправляет тело ответа в `/dev/null` (`-o /dev/null`), скрывает шкалу (`-s`) и выводит точный хронометраж каждого этапа соединения:
> 1. `time_namelookup` — время DNS-разрешения.
> 2. `time_connect` — время установления TCP-соединения (SYN-ACK).
> 3. `time_appconnect` — время завершения TLS/SSL рукопожатия.
> 4. `time_starttransfer` (TTFB) — время от отправки запроса до получения первого байта ответа.
> 5. `time_total` — суммарное время выполнения операции.

## Сводная матрица частых комбинаций флагов

| Задача                                  | Оптимальная комбинация флагов                                           |
| --------------------------------------- | ----------------------------------------------------------------------- |
| **Запрос к REST API (JSON)**            | `curl -sS -X POST -H "Content-Type: application/json" -d '{...}' <url>` |
| **Быстрая проверка HTTP-кода**          | `curl -s -o /dev/null -w "%{http_code}\n" <url>`                        |
| **Скачивание файла с докачкой**         | `curl -L -C - -O <url>`                                                 |
| **Полный дебаг TLS/HTTP запроса**       | `curl -v -k <url>`                                                      |
| **Игнорирование SSL и перенаправлений** | `curl -kL <url>`                                                        |
| **Отправка формы с файлом**             | `curl -F "file=@/path/to/file" <url>`                                   |
