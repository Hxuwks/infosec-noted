**ss** (Socket Statistics) — это современная высокопроизводительная утилита командной строки из пакета **iproute2**, пришедшая на замену устаревшей `netstat`.

> **Почему `ss` лучше:** В отличие от `netstat`, который медленно считывает текстовые файлы из `/proc/net/` при большом количестве соединений, `ss` получает информацию напрямую из ядра Linux через интерфейс `sock_diag` (модуль ядра Netlink). Это обеспечивает мгновенный вывод даже на высоконагруженных серверах с сотнями тысяч открытых сокетов.

**Синтаксис:**

```bash
ss [опции] [фильтр]

```

---

## 1. Основные флаги и параметры

### Выбор типа протокола / семейства адресов

* `-t` (`--tcp`) — отображать только **TCP** сокеты.
* `-u` (`--udp`) — отображать только **UDP** сокеты.
* `-w` (`--raw`) — отображать только **RAW** сокеты.
* `-x` (`--unix`) — отображать только **UNIX domain** сокеты.
* `-4` / `-6` — принудительно выводить сокеты только IPv4 или IPv6.

### Режимы вывода (Listening / All)

* `-l` (`--listening`) — выводить только **прослушиваемые** (Listening) сокеты, ожидает входящие соединения.
* `-a` (`--all`) — выводить **все** сокеты (и прослушиваемые `LISTEN`, и активные `ESTABLISHED`).
> *Примечание:* По умолчанию без флагов `-l` или `-a` `ss` показывает только активные установленные соединения (connected sockets).



### Форматирование и подробность данных

* `-n` (`--numeric`) — выводить адреса и порты в **числовом формате** без резолва в доменные имена (DNS) или имена служб (например, `22` вместо `ssh`). Ускоряет вывод.
* `-p` (`--processes`) — показать **PID и имя процесса**, которому принадлежит сокет (требует прав `root` / `sudo`).
* `-e` (`--extended`) — вывести расширенную информацию (например, сокетный инод, UID).
* `-s` (`--summary`) — вывести **сводную статистику** по всем типам сокетов (общее число, распределение по состояниям TCP, UDP, RAW).
* `-r` (`--resolve`) — попытаться разрешить числовые адреса в доменные имена (обратная операция `-n`).

## 2. Разбор полей вывода (Output Structure)

При вызове `ss -tulpn` вывод содержит следующие основные колонки:

```text
Netid State      Recv-Q Send-Q Local Address:Port        Peer Address:Port        Process                                   
tcp   LISTEN     0      128          0.0.0.0:22               0.0.0.0:*            users:(("sshd",pid=845,fd=3))

```

* **`Netid`** — тип сокета (`tcp`, `u_str` для Unix Stream и т.д.).
* **`State`** — текущее состояние сокета (`LISTEN`, `ESTABLISHED`, `TIME_WAIT` и др.).
* **`Recv-Q`** (Receive Queue) — количество байт в буфере приема (непрочитанных приложением).
* **`Send-Q`** (Send Queue) — количество байт в буфере отправки (не подтвержденных удаленной стороной).
* **`Local Address:Port`** — локальный IP-адрес и порт.
* **`Peer Address:Port`** — удаленный адрес и порт (для установленных соединений).
* **`Process`** — информация о процессе (`PID`, имя исполняемого файла), занявшем сокет (при использовании `-p`).

## 3. Практические примеры с детальным разбором

### 1. Просмотр всех прослушиваемых портов (Золотой стандарт)

```bash
sudo ss -tulpn

```

> **Что делает:** Выводит все слушающие (`-l`) TCP (`-t`) и UDP (`-u`) порты в числовом виде (`-n`) с указанием процессов (`-p`). Полный аналог классического `netstat -tulpn`.

---

### 2. Просмотр всех активных TCP-соединений

```bash
ss -atn

```

> **Что делает:** Показывает абсолютно все сокеты (`-a`), включая активные установленные и прослушиваемые, для протокола TCP (`-t`) в числовом формате (`-n`).

---

### 3. Фильтрация по состоянию (Только установленные соединения)

```bash
ss -t state established

```

> **Что делает:** Выводит только TCP-соединения, находящиеся в состоянии `ESTABLISHED`. Использование встроенного фильтра `state` работает гораздо быстрее, чем привычная конструкция с `grep`.

---

### 4. Поиск процесса, занимающего конкретный порт (например, 80)

```bash
sudo ss -tlp '( sport = :80 )'

```

> **Что делает:** Использует встроенный язык фильтрации `ss` для поиска процесса на локальном порту (`sport`) 80. Быстро и без лишнего шума.

---

### 5. Сводная статистика использования сокетов в системе

```bash
ss -s

```

> **Что делает:** Выводит компактный отчет по всем протоколам (Total, TCP, UDP, RAW, FRAG), показывая общее количество выделенных сокетов и их текущие состояния (alloc, tw, timewait, orphan). Отлично подходит для быстрой оценки нагрузки на ОС.

---

### 6. Фильтрация по удаленному IP-адресу или подсети

```bash
ss dst 192.168.1.50

```

> **Что делает:** Выводит все активные соединения, у которых адрес назначения (`dst`) совпадает с указанным IP. Полезно для аудита трафика конкретного хоста.

## 4. Состояния TCP-сокетов (Колонка State)

| Состояние | Описание |
| --- | --- |
| **`LISTEN`** | Сокет ожидает входящих подключений (серверный порт открыт). |
| **`SYN-SENT`** | Отправлен запрос на установление соединения (`SYN`), ожидается ответ. |
| **`SYN-RECV`** | Получен входящий `SYN`, отправлен `SYN-ACK`. Соединение в процессе установления. |
| **`ESTABLISHED`** | Соединение успешно установлено, идет активный обмен данными. |
| **`FIN-WAIT-1` / `FIN-WAIT-2**` | Локальная сторона инициировала закрытие соединения и ожидает подтверждения. |
| **`CLOSE-WAIT`** | Удаленная сторона закрыла соединение, локальное приложение еще не освободило сокет. |
| **`TIME-WAIT`** | Соединение закрыто, сокет выжидает таймаут для гарантии доставки запоздавших пакетов. |
| **`CLOSED`** | Сокет полностью закрыт и освобожден. |

---

## 5. Мощные фильтры `ss` (Встроенный синтаксис)

В отличие от `netstat`, требующего внешних утилит вроде `grep`, `ss` поддерживает собственный синтаксис фильтрации по портам, IP и состояниям, который передается в конце команды в одинарных кавычках:

* **Поиск по локальному порту:** `ss '( sport = :ssh )'` или `ss '( sport = :443 )'`
* **Поиск по удаленному порту:** `ss '( dport = :http or dport = :https )'`
* **Диапазон портов:** `ss '( sport \> 1024 and sport \< 65535 )'`
* **Фильтрация по сетям:** `ss src 192.168.1.0/24`
