### **Анатомия кастомного Ethernet-кадра: сборка в Scapy и побайтовый разбор в Wireshark**

Когда работаешь с высокоуровневыми библиотеками, сеть кажется абстракцией: вызвал `socket.send()`, и данные улетели. Но на самом низком уровне всё сводится к сырым байтам в заглавных полях Ethernet-кадра.

В этом посте мы разберем, как базово работать с Wireshark и Scapy, соберем кастомный фрейм с собственным сообщением, отправим его в сеть и прочитаем дамп байт за байтом.

#### 1. Из чего состоит Ethernet II Frame?

Вспомним базовую структуру кадра на канальном уровне (Data Link Layer):


```
╔══════════════════════════════╗
║    ETHERNET II FRAME (L2)    ║
╠══════════════════════════════╣
║ PREAMBLE (7 B)               ║
║ 10101010...                  ║
╠══════════════════════════════╣
║ SFD (1 B) │ 0xAB             ║
╠══════════════════════════════╣
║ DST MAC (6 B)                ║
║ AA:BB:CC:DD:EE:FF            ║
╠══════════════════════════════╣
║ SRC MAC (6 B)                ║
║ 11:22:33:44:55:66            ║
╠══════════════════════════════╣
║ TYPE / LEN (2 B)             ║
║ 0x0800 (IPv4) / 0x8888       ║
╠══════════════════════════════╣
║ DATA / PAYLOAD               ║
║ (46 ─ 1500 байт)             ║
║                              ║
║ "Hello, канальный уровень!"  ║
╠══════════════════════════════╣
║ FCS (4 B) │ CRC-32           ║
╚══════════════════════════════╝
```

Все его поля нам сейчас не обязательны — ключевыми для нас являются **DST MAC**, **SRC MAC**, **EtherType** и **Data (Payload)**.

Наша цель — выйти за рамки стандартных протоколов вроде IPv4 (`0x0800`) или ARP (`0x0806`), создать собственный кадр поверх L2 и посмотреть, как сниффер его декодирует.

#### 2. Собираем и отправляем фрейм через Scapy

Для генерации RAW-сокетов L2 используем Python и библиотеку `scapy` (запускать нужно с правами `root` / `sudo`):

```python
from scapy.all import Ether, sendp

# 1. Формируем L2-кадр
# Задаем Destination MAC, Source MAC и кастомный EtherType 
frame = ( 
	Ether(
	    dst="ff:ff:ff:ff:ff:ff",     # Broadcast
	    src="00:11:22:33:44:55",     # Кастомный SRC MAC
	    type=0x8888                  # Unassigned EtherType
	) 
	/ b"Hello, Wireshark! L2 RAW Data"
)
# 2. Отправляем фрейм напрямую в интерфейс
sendp(frame, iface="wlp3s0", verbose=False)
print("[+] Кастомный фрейм успешно отправлен в сеть!")
```

#### 3. Перехватываем кадр в Wireshark

Запускаем Wireshark на интерфейсе `eth0` и применяем дисплейный фильтр, чтобы отсечь весь лишний шум сети:

```
eth.type == 0x8888
```

#### 4. Читаем кадр побайтно (Hex-дамп)

Теперь откроем панель **Packet Bytes** (нижнее окно в Wireshark) и разберем сырой Hex-дамп полученного кадра по смещениям (offsets):

```
0000   ff ff ff ff ff ff 00 11 22 33 44 55 88 88 48 65   ........"3DU..He
0010   6c 6c 6f 2c 20 57 69 72 65 73 68 61 72 6b 21 20   llo, Wireshark! 
0020   4c 32 20 52 41 57 20 44 61 74 61                  L2 RAW Data
```
  

**Разбор байтов:**

- **`0x0000 – 0x0005` (6 байт):** `ff ff ff ff ff ff` — **DST MAC**. Кадр адресован всем устройствам в L2-сегменте (Broadcast).
    
- **`0x0006 – 0x000B` (6 байт):** `00 11 22 33 44 55` — **SRC MAC**. Наш подмененный MAC-адрес отправителя.
    
- **`0x000C – 0x000D` (2 байта):** `88 88` — **EtherType**. Обозначает тип вложенного протокола. Поскольку `0x8888` не задействован в реестре IANA, Wireshark понимает, что внутри нет IP/ARP-заголовков, и отображает тело как чистые данные (`Data`).
    
- **`0x000E+` (27 байт):** `48 65 6c 6c 6f...` — **Data (Payload)**. Наша ASCII-строка `"Hello, Wireshark! L2 RAW Data"`.
    

> **Где Преамбула и CRC (FCS)?**
> В дампе Wireshark мы их не увидим. Сетевая карта (NIC) обрабатывает преамбулу и проверяет контрольную сумму CRC-32 на **аппаратном уровне**, отбрасывая служебные структуры физического уровня до того, как кадр передается в ядро ОС и сниффер.
