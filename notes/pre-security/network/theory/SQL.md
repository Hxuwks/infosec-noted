## Часть 1. Основы SQL (Теория и практика)

**SQL (Structured Query Language)** — это язык запросов, используемый для общения с реляционными базами данных (PostgreSQL, MySQL, SQLite, MSSQL). Данные в таких базах хранятся в виде таблиц, состоящих из строк (записей) и столбцов (полей).

### 1. DDL (Data Definition Language) — Структура данных

Команды для создания и изменения структуры таблиц.

* **Создание таблицы:**
```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    password VARCHAR(50),
    role VARCHAR(20)
);

```



### 2. DML (Data Manipulation Language) — Управление данными

Команды для работы с самими записями (то, с чем чаще всего работает веб-приложение).

* **Вставка данных (INSERT):**
```sql
INSERT INTO users (id, username, password, role) 
VALUES (1, 'admin', 'supersecret', 'admin');

```


* **Обновление данных (UPDATE):**
```sql
UPDATE users SET role = 'user' WHERE username = 'hacker';

```


* **Удаление данных (DELETE):**
```sql
DELETE FROM users WHERE id = 5;

```



### 3. DQL (Data Query Language) — Выборка данных

Самый важный раздел для пентеста. Основа извлечения информации.

* **Базовая выборка (SELECT):**
```sql
SELECT username, role FROM users; 
-- Выведет только две колонки всех пользователей

SELECT * FROM users; 
-- Звездочка означает "вывести все колонки"

```


* **Фильтрация условий (WHERE):**
```sql
SELECT * FROM products WHERE category = 'Gifts' AND price < 100;

```


* **Поиск по шаблону (LIKE):**
```sql
SELECT * FROM users WHERE username LIKE '%adm%'; 
-- Найдет admin, sysadm, padme (знак % заменяет любые символы)

```


* **Сортировка и лимиты (ORDER BY, LIMIT):**
```sql
SELECT * FROM users ORDER BY id DESC LIMIT 5; 
-- Выведет 5 последних зарегистрированных пользователей

```



### 4. Объединение таблиц (JOIN) и Операции над множествами (UNION)

Основа для эксплуатации сложных инъекций.

* **JOIN (Связывание):** Позволяет склеить данные из двух таблиц по общему ключу.
```sql
SELECT users.username, orders.amount 
FROM users 
JOIN orders ON users.id = orders.user_id;

```


* **UNION (Объединение):** Берет результаты двух независимых запросов `SELECT` и склеивает их в одну итоговую таблицу. **Главное правило:** количество колонок и их типы данных в обоих запросах должны совпадать.
```sql
SELECT name, price FROM products
UNION
SELECT username, password FROM users;

```

## Часть 2. Теория SQL-инъекций (Как это работает)

**SQL-инъекция (SQLi)** — это уязвимость, возникающая из-за некорректной обработки пользовательского ввода.

### Механика уязвимости (Почему это происходит)

База данных не умеет отличать "код разработчика" от "данных пользователя". Если веб-сервер берет текст из поля ввода (например, `Gifts`) и склеивает его со строкой SQL-запроса, сервер БД выполнит всё это как единую команду.

**Цель атакующего:** выйти за пределы синтаксиса данных (например, закрыть кавычку `'`), написать свой вредоносный SQL-код и закомментировать оставшуюся часть оригинального запроса разработчика (через `--` или `#`).

### Основные классы SQL-инъекций

#### 1. In-Band (Классические)

Самый простой и удобный вид. Результат инъекции выводится прямо на веб-странице, которую вы атакуете.

* **Union-Based:** Мы используем оператор `UNION`, чтобы приклеить результаты нашего вредоносного запроса (например, вывод паролей из таблицы `users`) к легитимному ответу (например, списку товаров).
* **Error-Based:** Мы намеренно составляем синтаксически неверный запрос или вызываем математическую ошибку. Если сервер настроен плохо, он выведет текст ошибки базы данных прямо на экран, и в этом тексте мы заставим его распечатать нужные нам данные.

#### 2. Inferential (Blind / Слепые)

Применяются, когда веб-приложение уязвимо, но не выводит данные или ошибки на экран. Мы можем только задавать базе данных вопросы формата "Правда / Ложь" и анализировать ее реакцию.

* **Boolean-Based Blind:** Мы внедряем условие (например, `AND (SELECT SUBSTRING(password, 1, 1) FROM users) = 'a'`). Если первая буква пароля действительно "a", страница загрузится нормально. Если нет — страница может не загрузить картинки или вернуть 404. Мы посимвольно перебираем базу данных.
* **Time-Based Blind:** Применяется, когда страница вообще никак визуально не меняется. Мы используем команду задержки времени (например, `SLEEP(5)` или `pg_sleep(5)`). Логика: "Если первая буква пароля 'a', усни на 5 секунд". Если страница загрузилась мгновенно — мы не угадали. Если грузилась 5 секунд — мы нашли первый символ.

#### 3. Out-of-Band (OOB)

Самый редкий и сложный тип. Применяется, когда сервер уязвим, но не возвращает ни данных, ни задержек по времени (например, асинхронные запросы). В этом случае мы заставляем саму базу данных (её внутренние сетевые модули) сделать внешний HTTP или DNS запрос на наш подконтрольный хакерский сервер, передав украденные данные в URL или имени поддомена.

### Методология применения (Как мыслить при атаке)

1. **Fuzzing (Поиск точки входа):** Подстановка во все параметры (URL, формы, куки, заголовки) символов-разрушителей: `'`, `"`, `\`, `;`.
2. **Определение контекста:** Понять, куда попал наш пейлоад. В числовое поле? (тогда кавычка не нужна). В строковое? (нужна кавычка).
3. **Балансировка запроса:** Подобрать правильное закрытие скобок и кавычек, чтобы код стал валидным, а затем отрезать "хвост" запроса комментарием (`-- -`).
4. **Сбор данных (Recon):** Выяснить тип базы данных (через специфичные для MySQL/PostgreSQL/SQLite функции), количество колонок и их типы.
5. **Эксплуатация:** Извлечь имена таблиц, затем имена колонок, затем сами данные (логины, пароли, токены).
